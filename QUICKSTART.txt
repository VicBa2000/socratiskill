================================================================================
  SOCRATISKILL - Quick Start + How to Use
================================================================================

  A Claude Code plugin that turns the CLI into a socratic mentor: asks
  before answering, escalates hints on struggle, reviews past mistakes,
  flags antipatterns, and keeps a learning journal.


================================================================================
  1. QUICK START (fresh install, 3 minutes)
================================================================================

  Prerequisites:
    - bun        https://bun.com/docs/installation
    - node       (any recent LTS; already bundled with most setups)
    - Claude Code with plugin + hook support


  ------------------------------------------------------------------
  1.1 WHAT YOU CONFIGURE WHEN (read this first)
  ------------------------------------------------------------------

  Socratiskill installs at the USER level, not per project. Everything
  in 1.2 below is done EXACTLY ONCE per machine.

    [ONE-TIME]      The install steps in section 1.2 (path A: 2
                    steps, ~1 minute; path B: 3 steps for devs).
                    Hooks come from the plugin manifest
                    (hooks/hooks.json), so they apply globally to
                    every Claude Code session in every project.
                    State lives in ~/.claude/socratic/.

    [PER PROJECT]   Nothing. The mentor follows you across every
                    project / working directory automatically. The
                    plugin manifest hooks fire even in projects that
                    have their own .claude/settings.json (which would
                    otherwise override user-level hook entries).

    [PER SESSION]   Nothing. Each new Claude Code console you launch
                    picks up the hooks and the plugin automatically.
                    You don't run `/plugin install` or anything else
                    on session start.

                    Per-session toggles you may want:
                      /socratiskill:socratic off    -> soft mute (keeps
                                                       hook running but
                                                       injects only a
                                                       30-token silencer)
                      /socratiskill:socratic pause  -> TRUE bypass (zero
                                                       tokens; renames
                                                       profile aside)
                      /socratiskill:socratic on     -> undo `off`
                      /socratiskill:socratic resume -> undo `pause`
                    All four are persisted across sessions.


  ------------------------------------------------------------------
  1.2 ONE-TIME SETUP (run these once per machine)
  ------------------------------------------------------------------

  There are two install paths. Almost everyone wants path A.

  === Path A (RECOMMENDED): install from GitHub ====================

  You do NOT clone anything. Claude Code fetches the plugin for you
  and can also pull updates later with `/plugin update`.

  Step 1. Inside a Claude Code session:
    /plugin marketplace add VicBa2000/socratiskill
    /plugin install socratiskill@socratiskill
    /reload-plugins

  That's it. Claude Code downloads the plugin into
  `~/.claude/plugins/marketplaces/socratiskill/` for you. To get
  future updates, run:
    /plugin update socratiskill@socratiskill

  Step 2. Calibrate:
    /socratiskill:socratic calibrate

  Skip Path B unless you plan to edit the plugin source.

  === Path B: install from a local clone (dev / offline mode) ======

  Use this only if you want to edit the plugin code directly.
  Updates are manual: `git pull` in the clone, then re-install.

  Step 1. Clone the plugin repo. The command below ALWAYS drops the
  files at ~/socratiskill (your HOME folder), no matter what
  directory your terminal is currently `cd`'d into.
    git clone https://github.com/VicBa2000/socratiskill ~/socratiskill

  >>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>
  >  WHERE DO THE FILES LAND?                                      >
  >                                                                >
  >  `git clone <url> ~/socratiskill` ignores your terminal's      >
  >  current directory. It writes the repo into your home folder, >
  >  which on each OS is:                                          >
  >                                                                >
  >    Windows (Git Bash):  C:\Users\<you>\socratiskill            >
  >    macOS:               /Users/<you>/socratiskill              >
  >    Linux:               /home/<you>/socratiskill               >
  >                                                                >
  >  Even if you run the command from Desktop/, Documents/,        >
  >  Pictures/, or anywhere else — the files DO NOT appear there. >
  >  They appear in your home folder, inside a new `socratiskill/` >
  >  subfolder. This is normal, not malware; `git clone` obeys the >
  >  destination path in the command, not your current location.   >
  >                                                                >
  >  If you want the repo somewhere else, change the destination:  >
  >    git clone <url> ~/Desktop/socratiskill                      >
  >    git clone <url> /d/code/socratiskill                        >
  >  Whatever path you pick, WRITE IT DOWN — Step 2 needs it.      >
  >>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>>

  Step 2. Tell Claude Code about the plugin (inside a Claude Code
  session). IMPORTANT: the `/plugin` CLI does NOT reliably expand
  `~` on Windows — always pass the ABSOLUTE path.

    /plugin marketplace add <absolute-path-to-repo>
    /plugin install socratiskill@socratiskill
    /reload-plugins

    Concrete examples (forward slashes work on Windows):
      /plugin marketplace add C:/Users/<you>/socratiskill
      /plugin marketplace add /Users/<you>/socratiskill
      /plugin marketplace add /home/<you>/socratiskill

    After `marketplace add`, verify the registration actually
    persisted before moving on:

      cat ~/.claude/plugins/known_marketplaces.json

    You should see a "socratiskill" entry with the exact path you
    passed. If it is NOT there, the add silently failed — Claude
    Code can print "Successfully added marketplace: socratiskill"
    even when the directory does not contain
    `.claude-plugin/marketplace.json` (for example because the `~`
    was taken literally, or you pointed at an empty/partial dir).
    Retry with a correct absolute path before Step 3.

  To update later (path B only):
    cd ~/socratiskill && git pull
    # then, inside Claude Code:
    /plugin update socratiskill@socratiskill

  Step 3. Calibrate your pedagogical level (one question):
    /socratiskill:socratic calibrate
    -> pick 1..5 (Novice / Basic / Intermediate / Advanced / Expert).
    -> this also creates ~/.claude/socratic/profile.json the first time.

  You are done. From now on, every Claude Code console you open in
  any project responds as a socratic mentor adapted to your level.
  Keep coding normally.

  Optional: if for some reason you do NOT want to install via the
  plugin system (e.g. you want hook entries written directly into
  ~/.claude/settings.json), use the legacy installer instead of
  Step 2:
    bash ~/socratiskill/scripts/install.sh
  Do NOT mix both — running install.sh AND installing as a plugin
  would register the hooks twice, doubling the token cost per turn.

  >> WARNING: THE LEGACY PATH DOES NOT REGISTER THE GATE. <<
  install.sh writes only the UserPromptSubmit and Stop entries. The
  PreToolUse hook — the one that turns your level into enforcement
  instead of a suggestion — comes from the plugin manifest
  (hooks/hooks.json) and is NOT written to settings.json.

  What that means in practice: at levels 2-5 the mentor still TELLS
  Claude it may not edit your files, and Claude will mostly comply,
  but nothing STOPS it. And it fails silently — an advisory level
  looks identical to an enforced one right up until Claude writes a
  body you were supposed to write. If you want the axis enforced,
  use Path A or Path B Step 2 above.


================================================================================
  2. QUICK USAGE (every command, by example)
================================================================================

  Everything goes through /socratiskill:socratic <subcommand>. Nothing
  here needs a flag or a config file — copy a line, paste it, done.

  If you only ever remember three:

    /socratiskill:socratic                     where am I right now
    /socratiskill:socratic level 3             how much of the work is mine
    /socratiskill:socratic ship prod is down   get out of the way, 10 min


  ------------------------------------------------------------------
  2.1 THE ONE DIAL: `level`
  ------------------------------------------------------------------
  The level answers ONE question: how much of the work is YOURS?
  Higher = the agent does LESS. It is not "how much it explains".

    /socratiskill:socratic level 1   Implementer — it writes, you read
                                     and get questioned about it
    /socratiskill:socratic level 2   Framer — it writes structure and
                                     trivial bodies; the load-bearing
                                     logic is yours
    /socratiskill:socratic level 3   Architect — it writes skeletons and
                                     signatures; EVERY body is yours
    /socratiskill:socratic level 4   Guide — it writes nothing; it breaks
                                     the problem down and points at prior
                                     art in your repo
    /socratiskill:socratic level 5   Socratic — it writes nothing and
                                     directs nothing. It asks.

  What you get back:

    level updated: 2 -> 3 (architect)

  At levels 2-5 the agent may CREATE files but never EDIT yours, and
  what it creates is capped:

    level 2   8 new files/day    up to 8 executable statements each
    level 3   6 new files/day    0 statements — skeletons only
    level 4   4 new files/day    0 statements
    level 5   3 new files/day    0 statements

  Every new file is also capped at 80 lines, at every level.

  If a level ever feels wrong, do not fight it — change it. The wrong
  level is the single most common reason this plugin feels annoying
  instead of useful.


  ------------------------------------------------------------------
  2.2 WHEN YOU JUST NEED THE CODE NOW: `ship`
  ------------------------------------------------------------------
  A logged, expiring escape. The agent writes normally until it runs
  out, then the level re-arms by itself. No nagging, no confirmation
  prompt, no comment on your choice.

    /socratiskill:socratic ship prod is down
        -> escape open for 10 min. logged: prod is down

    /socratiskill:socratic ship 25 demo del viernes
        -> escape open for 25 min. logged: demo del viernes

  GOTCHA — THE MINUTES GO FIRST, not last. A leading number is read as
  the duration:

    ship 3 things broke       -> 3 MINUTES, reason "things broke"
    ship three things broke   -> 10 minutes (default), full reason kept

  A reason is required; it is the whole accountability mechanism.

    /socratiskill:socratic ship        -> error: a reason is required

  Inspect or close one early:

    bun run <plugin>/scripts/escape.ts --status
    bun run <plugin>/scripts/escape.ts --end

  `ship` is a no-op at levels 1 and 6 — the agent already writes freely
  there, so there is nothing to escape from.


  ------------------------------------------------------------------
  2.3 MID-CONVERSATION NUDGES
  ------------------------------------------------------------------
  These move the hint ladder inside the CURRENT problem. They do not
  change your level — getting stuck on one bug should not demote you.

    /socratiskill:socratic hint       one rung more direct (+1)
    /socratiskill:socratic faster     same thing, different name
    /socratiskill:socratic slower     two rungs more socratic (-2)

  `slower` is deliberately twice as strong as `hint`: it is easy to
  drift into being spoon-fed one rung at a time, and hard to climb back.

    /socratiskill:socratic challenge

  Arms anti-adulation for your NEXT message only. Use it when you want
  your idea attacked instead of praised — the agent goes looking for
  what is wrong with it rather than agreeing with you.


  ------------------------------------------------------------------
  2.4 DELIBERATE PRACTICE: `drill`
  ------------------------------------------------------------------
  Exercises drawn from YOUR repo, not from a textbook.

    /socratiskill:socratic drill analyze
        You get quizzed on code that already exists. The script picks
        the file on rotation. Works at ANY level — reading was never
        the restricted half.

    /socratiskill:socratic drill analyze src/auth/session.ts
        Same, on a file you choose.

    /socratiskill:socratic drill build
        You implement a bounded task from scratch. Needs level 3+;
        below that the agent writes the bodies and the drill measures
        nothing.

    /socratiskill:socratic drill fix
        The one that trains the skill nobody practices: LOCATING a
        change in code you did not write. You get a concrete change
        request and have to work out WHERE it goes before any code is
        written. The agent will not name the function or quote the
        line — that IS the exercise. Needs level 3+.

    /socratiskill:socratic drill status    what is running
    /socratiskill:socratic drill done      close it (build and fix
                                           report the lines you wrote)
    /socratiskill:socratic drill cancel    abandon it

  The agent never edits your files to plant a bug for you to find. A
  manufactured exercise is worse than no exercise, so it works on the
  code exactly as it is.


  ------------------------------------------------------------------
  2.5 TEACH IT BACK: `teach` / `endteach`
  ------------------------------------------------------------------
  Role inversion (Feynman). You explain, it probes for the gaps.

    /socratiskill:socratic teach event loop
    /socratiskill:socratic teach por que un indice acelera un JOIN
        ... you explain; it asks until something does not hold up ...
    /socratiskill:socratic endteach
        -> prints the gaps it found; the journal harvests them

  One session at a time — running `teach` while one is open tells you
  to `endteach` first.


  ------------------------------------------------------------------
  2.6 SPACED REPETITION: `review`
  ------------------------------------------------------------------
    /socratiskill:socratic review

  Pulls one card that is due (Leitner) and asks ONE verifiable question
  about it. If nothing is due you get exactly:

    no review cards due

  Cards are created automatically from what you got wrong. You never
  add them by hand.


  ------------------------------------------------------------------
  2.7 WHAT YOU ACTUALLY DID: `status` / `journal`
  ------------------------------------------------------------------
    /socratiskill:socratic            same as `status`
    /socratiskill:socratic status     level, whether it is on, streak,
                                      budget left today, autonomy

  The autonomy number is measured from git, not from the agent's
  opinion of you: while the gate is armed the agent cannot edit, so
  whatever shows up in the working tree came from your hands. It is
  reported with no congratulation and no softening — an honest number
  you can act on is the entire product.

    /socratiskill:socratic journal today
    /socratiskill:socratic journal week
    /socratiskill:socratic journal month

  Regenerates from the session files and prints it; also writes
  ~/.claude/socratic/journal/<file>.md for later.


  ------------------------------------------------------------------
  2.8 CALIBRATION: `calibrate` / `accept`
  ------------------------------------------------------------------
    /socratiskill:socratic calibrate

  Run once on a fresh install: a short self-assessment plus one
  question, and it sets your starting level.

  After that the plugin watches how you do and may SUGGEST a change. It
  never moves you on its own:

    /socratiskill:socratic accept     apply the suggested change

  If nothing is pending it says so and changes nothing. Calibration
  clamps at 5 and can never promote you to 6 by any path — a plugin
  that promoted you to "the agent does everything" would be sabotaging
  itself.


  ------------------------------------------------------------------
  2.9 TURNING IT OFF (three different strengths)
  ------------------------------------------------------------------
    /socratiskill:socratic off        soft mute, ~30 tokens/turn,
                                      instant, state kept
    /socratiskill:socratic on         undo `off`

    /socratiskill:socratic pause      true bypass, ZERO tokens/turn,
                                      state kept
    /socratiskill:socratic resume     undo `pause`

  Both survive across sessions and both are idempotent. Reach for
  `pause` when you want it genuinely invisible for a stretch of work
  without losing your level, streak or error-map.

  Heavier hammers, in order:

    /plugin disable socratiskill      no hooks at all
    /plugin uninstall socratiskill    full removal

    /socratiskill:socratic reset      DESTRUCTIVE — wipes profile,
                                      journal, error-map, sessions
                                      and antipatterns
    /socratiskill:socratic reset force   same, skipping the prompt

  Bare `reset` only asks for confirmation; it writes nothing until you
  pass `force`.


  ------------------------------------------------------------------
  2.10 A REALISTIC FIRST HOUR
  ------------------------------------------------------------------
    /socratiskill:socratic calibrate         once, ever
    /socratiskill:socratic                   see where it put you
    /socratiskill:socratic level 3           skeletons only; bodies mine

    ... work normally. Ask for a new module. The agent creates the file
        with imports, types, signatures and a TODO in each body, then
        stops. You fill the bodies. It cannot edit that file afterwards,
        so what lands in the tree is yours. ...

    /socratiskill:socratic slower                    too direct
    /socratiskill:socratic ship 15 pipeline is red   real deadline
    /socratiskill:socratic drill fix                 train locating
    /socratiskill:socratic journal today             what happened

  If it feels bureaucratic rather than useful, the level is probably
  wrong for what you are doing today. Move it. That is what it is for.


================================================================================
  3. HOW TO USE (daily cheatsheet)
================================================================================

  Everything is dispatched through /socratiskill:socratic <subcommand>.

  ------------------------------------------------------------------
  3.1 CHECK YOUR CURRENT STATE
  ------------------------------------------------------------------
    /socratiskill:socratic              -> status (same as below)
    /socratiskill:socratic status       -> enabled, level, streak,
                                           budget left today, autonomy

    Reads: ~/.claude/socratic/profile.json

  ------------------------------------------------------------------
  3.2 TURN THE MENTOR ON / OFF / PAUSE
  ------------------------------------------------------------------
    /socratiskill:socratic off          -> SOFT mute (hook still runs;
                                           injects ~30-token DISABLED
                                           silencer telling the model
                                           to act as default Claude Code)
    /socratiskill:socratic on           -> undo `off`

    /socratiskill:socratic pause        -> TRUE bypass (renames
                                           profile.json aside; hook
                                           short-circuits at zero token
                                           cost, ~5ms)
    /socratiskill:socratic resume       -> undo `pause`

    When to use which:

      DEFAULT      full pedagogy, ~200-400 tokens/turn of context
      `off`        instant toggle, ~30 tokens/turn, state preserved
      `pause`      zero tokens/turn, state preserved in .paused file
      /plugin disable socratiskill       no hooks at all (Claude Code
                                         feature; reverse with /enable)
      /plugin uninstall socratiskill     full removal (also run
                                         scripts/uninstall.sh first if
                                         you used the legacy install)

    `off` and `pause` are persisted across sessions. The shell-script
    fallbacks bash scripts/pause.sh and bash scripts/resume.sh do the
    exact same thing — useful if the dispatcher is broken or you want
    to script it from a CI / wrapper.

  ------------------------------------------------------------------
  3.3 CHANGE THE LEVEL
  ------------------------------------------------------------------
    /socratiskill:socratic level 3      -> set the axis (1..5)

    There is ONE pedagogical setting. The level answers one question
    and everything else follows from the answer:

              HOW MUCH OF THE WORK IS YOURS?

    Going UP means Claude does LESS for you, not more. That is the
    point: a plugin that rewarded competence by writing more of your
    code would be training the atrophy it exists to fight.

      1 Implementer   Claude writes the code
          Restate -> plan -> teach -> ONE comprehension question.
          END turn, wait for approval. MAX 30 lines / 1 file per
          turn. Every line still has to teach.
          Rung 5 (full explanation).

      2 Framer        Claude frames, you write the logic
          It creates the file with structure, imports, signatures
          and the trivial bodies; the load-bearing logic is yours.
          Hands you one MODULE at a time with acceptance criteria.
          Rungs 4-5.

      3 Architect     Claude writes skeletons, you write bodies
          Signatures and TODOs only -- ZERO executable statements
          per file. Hands you one UNIT at a time.
          Rungs 3-4.  <- the working level for most people

      4 Guide         Claude writes nothing
          Breaks the problem into ordered subproblems and points
          you at code you already wrote elsewhere in your repo.
          Hands you one SUBPROBLEM at a time.
          Rungs 2-3.

      5 Socratic      Claude writes nothing and directs nothing
          Questions only. It will not even decompose for you.
          Rungs 0-1.

    The gate is real above level 1: Write/Edit on an existing file
    is DENIED by a PreToolUse hook, along with subagent delegation
    and bash used as an editor (cat >, tee, sed -i, git apply).
    Running your tests, git, builds and linters stays allowed --
    that is exactly what you should be doing.

    At levels 2-5 Claude may still CREATE files that do not exist
    (an empty package.json, a blank component), within a daily
    budget and a per-file line cap. Typing boilerplate teaches
    nothing. But what it puts in them is checked: at levels 3-5 a
    new file must contain zero executable statements.

    `mode learn` / `mode productive` are GONE. They said the same
    thing the level now says, and "I need to ship right now" is
    covered by `ship` (see 3.9).

  ------------------------------------------------------------------
  ------------------------------------------------------------------
  3.4 ASK FOR MORE / LESS GUIDANCE DURING A CONVERSATION
  ------------------------------------------------------------------
    /socratiskill:socratic hint         -> raise scaffolding (+1)
    /socratiskill:socratic faster       -> same as hint (alias, less filler)
    /socratiskill:socratic slower       -> drop scaffolding (-2, more socratic)
    /socratiskill:socratic challenge    -> next turn: anti-adulation mode

    These adjust THIS session's hint level. The mentor's automatic
    escalation (based on correct/wrong answers) continues in parallel.

  ------------------------------------------------------------------
  3.5 TEACH SOMETHING TO CLAUDE (Feynman mode)
  ------------------------------------------------------------------
    /socratiskill:socratic teach <topic>
    ... (you explain; Claude probes with questions, doesn't teach) ...
    /socratiskill:socratic endteach

    Example:
      /socratiskill:socratic teach closures
      > "A closure is a function that remembers variables from the
      > outer scope even after the outer function returned..."
      Claude: "Walk me through an example where two closures share
      the same outer variable but at different times?"
      ... after 3-4 turns ...
      /socratiskill:socratic endteach
      -> "teach ended: closures (Nmin, K gaps detected)"

    Gaps go to the session file and later to the daily journal.

  ------------------------------------------------------------------
  3.6 REVIEW PAST MISTAKES (spaced repetition, Leitner)
  ------------------------------------------------------------------
    /socratiskill:socratic review

    If you have a card due (an old topic you failed), Claude poses one
    verifiable question about it. Your answer updates the Leitner box
    (1 -> 3 -> 7 -> 14 -> 30 days). Two consecutive right answers
    advance the card; one wrong answer resets it.

    If no cards are due:
      "no review cards due"

  ------------------------------------------------------------------
  3.7 SEE WHAT YOU ACTUALLY LEARNED (journal)
  ------------------------------------------------------------------
    /socratiskill:socratic journal              -> daily (today)
    /socratiskill:socratic journal week         -> ISO week (Mon-Sun)
    /socratiskill:socratic journal month        -> calendar month

    Generates a markdown rollup from your session files, categorizing
    topics into Learned / Struggled / Practiced, plus any Feynman
    teach summaries and a Leitner snapshot. Saved under
    ~/.claude/socratic/journal/.

  ------------------------------------------------------------------
  3.8 ACCEPT A CALIBRATION SUGGESTION
  ------------------------------------------------------------------
    The level-up pipeline is intentionally conservative to avoid
    premature / sycophantic promotions. In order, to climb from
    level X to level X+1 you need:

      1. Per-level threshold of correct answers in a window:
           L1 -> 10/12   L2 -> 7/9   L3 -> 5/7   L4 -> 5/7
      2. Weighted average of those correct answers >= 0.5,
         where each correct is weighted by (5 - hintLevel)/5.
         Scaffolded correctness carries low weight on purpose.
      3. Topic diversity: at least ceil(needed/2) distinct topics.
      4. Depth diversity: at least ceil(needed/2) of the correct
         answers must have been with hintLevel <= 2 (analogy or
         lower scaffolding).
      5. A 3-turn diagnostic quiz: the mentor quietly inserts
         comprehension questions at the next level in the flow.
         You must pass >= 2/3. During this quiz an anti-adulation
         instruction is active: vague or hand-wavy answers are
         graded as FAIL, not pass.

    Only after all of the above does the mentor surface "calibration:
    suggest level X -> Y" in context. Run:

      /socratiskill:socratic accept

    This applies the change and resets the session's hint state
    to the new level's initial value. You can also bypass the
    pipeline entirely with `/socratiskill:socratic level N`.

    Downgrades do NOT require a diagnostic — they apply directly
    after 3 wrong answers in 5 turns, because being stuck above
    your level is worse than a false downgrade.


  ------------------------------------------------------------------
  3.9 WHEN YOU NEED TO SHIP RIGHT NOW
  ------------------------------------------------------------------
    /socratiskill:socratic ship "prod hotfix"
    /socratiskill:socratic ship 25 "demo del viernes"
    /socratiskill:socratic ship --status | --end

    Claude writes normally until the window expires (default 10 min),
    then your level re-arms by itself. A reason is REQUIRED and gets
    logged.

    Claude will not question it, will not remind you of your goals,
    and will not act disappointed. Real work has real deadlines, and
    a lock with no exit is a lock you uninstall the first Friday it
    gets in the way. The log is the accountability; commentary is
    not. (This replaces v0.4's `unlock` and `mode productive`, which
    were asking the same thing in two different ways.)

  ------------------------------------------------------------------
  3.9b THE HANDOFF (levels 2-4)
  ------------------------------------------------------------------
    At levels 2, 3 and 4 the work comes to you one piece at a time:

      frame -> name the unit -> acceptance criteria -> STOP
            -> you implement -> Claude evaluates -> next

    Claude states the acceptance criteria BEFORE any code exists.
    That is what makes the review objective instead of a matter of
    taste. Then it stops and waits for you.

    When you come back it reviews against those criteria: it points
    at the line, names the problem, and asks what you would do. It
    will NOT hand you the corrected version -- that is just writing
    the code with extra steps.

    If your implementation misses a criterion, it gets handed back,
    not fixed. That is the most useful turn in the whole loop: the
    only moment you find your own gap while it is still warm.

  ------------------------------------------------------------------
  3.9c THE AUTONOMY NUMBER
  ------------------------------------------------------------------
    /socratiskill:socratic status  -> includes today's report:

      autonomy — 2026-09-01 (level 3)
      you wrote: +127 / -34 lines in /home/you/project
      created by the agent: +18 lines across 2 file(s) (excluded above)
      turns where you produced code: 6 / 11
      average ladder rung: 2.3 (lower = you needed less help)
      escapes: 1 (5 min total) — prod hotfix

    The line count comes from git, not from Claude's opinion: with the
    gate armed, whatever showed up in your working tree came from you.
    It survives committing mid-session and counts files you have not
    `git add`ed yet.

    Baselines are per REPOSITORY and reset daily, so switching
    projects mid-day measures the new one instead of quietly
    reporting on the one you left.

    Two honesty rules worth knowing:
      - Lines Claude wrote by CREATING a file are subtracted exactly
        (the gate saw every one of them).
      - Lines it wrote during a `ship` window cannot be told apart
        from yours, so the report SAYS SO instead of pretending.

    Totals per period land in your journal under "## Autonomy".

  ------------------------------------------------------------------
  ------------------------------------------------------------------
  3.10 DRILLS (deliberate practice from your own repo)
  ------------------------------------------------------------------
    /socratiskill:socratic drill analyze          -> quiz on your code
    /socratiskill:socratic drill analyze <file>   -> a specific file
    /socratiskill:socratic drill build            -> build from zero
    /socratiskill:socratic drill fix              -> change existing code
    /socratiskill:socratic drill status|done|cancel

    Tres ejercicios, uno por habilidad que se oxida:

      analyze  leer          "no podria navegar este proyecto solo"
      build    escribir      "no podria arrancar de una pagina en blanco"
      fix      UBICAR        "no sabria por donde empezar en codigo ajeno"

    ANALYZE answers "could I still find my way around this project
    without an agent?". It picks a source file from your repo — the
    script picks it, on rotation, so neither you nor Claude can choose
    something comfortable — then asks one question per turn, working
    up from "what does this do" to "what breaks if I delete this
    line". Wrong answers become Leitner review cards and come back
    scheduled. Works at ANY level -- reading was never the half that
    got restricted.

    BUILD answers "could I still start from a blank page?". It needs
    level 3 or higher -- below that Claude writes the bodies and the
    drill measures nothing. It proposes one bounded task from your repo
    and agrees the acceptance criteria with you BEFORE any code
    exists, then stays out of the way. `drill done` reports how many
    lines you wrote and reviews against those criteria.

    FIX answers "podria cambiar codigo que no escribi yo?". Es el hueco
    que los otros dos dejan: analyze entrena LEER, build entrena
    ESCRIBIR DESDE CERO, y ninguno entrena UBICAR. Necesita nivel 3+.

    Va en dos fases, y la primera ES el ejercicio:

      1. LOCATE   Claude lee un archivo de la rotacion y plantea UN
                  pedido de cambio concreto. Despues pregunta donde
                  tocarias y por que — sin nombrar la funcion ni citar
                  la linea. Si te equivocas de lugar no te corrige:
                  te hace una pregunta mas angosta.
      2. IMPLEMENT  Recien cuando tu respuesta se sostiene. A partir
                  de ahi es un handoff normal.

    `drill done` reporta si lo ubicaste al primer intento y cuantas
    lineas escribiste. "Located first try: no" no es un reproche, es
    LA medicion: es el numero que dice si el musculo de navegar sigue
    ahi.

    NUNCA planta un bug en tu repo. Trabaja sobre el codigo tal cual
    esta y encuentra un hueco real leyendo. Si el archivo no ofrece
    nada que valga la pena, lo dice y cancela — un ejercicio fabricado
    es peor que ningun ejercicio.

    Only one drill runs at a time. `drill cancel` drops it.

  ------------------------------------------------------------------
  4.1 DAILY CODING (level 3)
  ------------------------------------------------------------------
    Start: /socratiskill:socratic level 3
    Claude sets up the files and signatures, hands you one unit at a

  ------------------------------------------------------------------
    Start: /socratiskill:socratic level 2
    Ask the topic. Claude frames the module and hands you the part
    that actually decides something, with verification questions.
    If it goes too fast: /socratiskill:socratic slower
    If too slow:        /socratiskill:socratic faster
    Once you think you get it:
      /socratiskill:socratic teach <topic>
      (explain it in your own words; Claude probes for gaps)
      /socratiskill:socratic endteach

  ------------------------------------------------------------------
  4.3 WEEKLY REFRESHER
  ------------------------------------------------------------------
    Every few days:
      /socratiskill:socratic review
      (answer the card; Claude schedules the next review)
    Once a week:
      /socratiskill:socratic journal week
      (see which topics resurfaced as "struggled")

================================================================================
  6. TROUBLESHOOTING
================================================================================

  Problem: /socratiskill:socratic status shows "enabled: false".
    Fix:   /socratiskill:socratic on

  Problem: Subcommands behave weird after editing SKILL.md.
    Fix:   /reload-plugins (Claude Code caches the SKILL.md body).
           Scripts (*.ts, *.sh) are picked up on every call — no reload
           needed for those.

  Problem: "Welcome to Socratiskill" never shows up.
    Fix:   You already calibrated. To redo:
             /socratiskill:socratic calibrate force

  Problem: "no review cards due" but you know you have struggled topics.
    Fix:   Open ~/.claude/socratic/error-map.json. A card is due when
           next_review_at <= now AND resolved == false. If everything
           is upcoming, you just have to wait.

  Problem: HINT_META block shows up as visible text in your client.
    Cause: Your markdown renderer doesn't strip HTML comments.
    Fix:   The block is harmless telemetry. Open an issue; we might
           add an opt-in alternative format.

  Problem: You want to start completely fresh.
    Fix:   bash ~/socratiskill/scripts/uninstall.sh --purge
           Then /plugin install socratiskill@socratiskill again
           and /socratiskill:socratic calibrate.

  Problem: Hooks fire twice per turn (you see two SOCRATIC CONTEXT
           blocks, or counters are doubling).
    Cause: You ran both `bash scripts/install.sh` AND installed via
           `/plugin install`, so the hooks are registered twice
           (once in ~/.claude/settings.json, once via the plugin
           manifest).
    Fix:   bash ~/socratiskill/scripts/uninstall.sh --keep-state
           This removes the settings.json entries; the plugin
           manifest hooks remain and you have a single firing.

  Problem: Plugin appears to be doing nothing in a specific project.
    Cause: That project has its own .claude/settings.json. Before
           v0.2 the user-level hooks did not propagate; now they do
           because plugin manifest hooks are global. If you are still
           on v0.1 or used the legacy install path, run:
             cd <that-project>
             CLAUDE_SETTINGS="$(pwd)/.claude/settings.json" \
               bash ~/socratiskill/scripts/install-hooks.sh

  Problem: I want zero token cost without uninstalling.
    Fix:   /socratiskill:socratic pause
           Resume any time with /socratiskill:socratic resume.

  Problem: I disabled / paused / uninstalled the plugin, but the
           model still emits HINT_META or restate/plan preambles.
    Cause: CONTEXT PERSISTENCE. When the plugin was active earlier in
           THIS session, its SKILL.md and META PROTOCOL instructions
           were injected into the model's context window. Those
           instructions cannot be retroactively removed — an LLM has
           no "forget that earlier system-reminder" operation.
           Pause / disable / uninstall stop the hook from injecting
           NEW context, but they do not un-teach what the model
           already absorbed in this session.
    Fix:   Restart Claude Code (close the CLI, relaunch). The new
           session starts with no socratic context loaded, so the
           model no longer emits HINT_META or restate/plan blocks.
           `pause` also emits a one-shot silencer on the very first
           turn after pausing (v0.2+), which helps within the same
           session — but a restart is the only full guarantee.

  Problem: I uninstalled the plugin but still see "※ recap: ..." lines.
    Cause: That is a Claude Code / model behavior, not a socratiskill
           feature. A grep for "recap" in this repo returns zero
           matches — we never inject that keyword. The recap-summary
           lines appear in any Claude Code session, regardless of
           whether socratiskill is installed.
    Fix:   Not ours to fix. If you want the model to stop producing
           those auto-summaries, that's a Claude Code / model prompt
           question, not a plugin one.

  Problem: How do I get the latest version of the plugin?
    If you installed via path A (GitHub source):
           /plugin update socratiskill@socratiskill
           (Claude Code does a `git pull` for you under the hood.)
    If you installed via path B (local clone):
           cd ~/socratiskill && git pull
           # then, inside Claude Code:
           /plugin update socratiskill@socratiskill
           (The `/plugin update` button alone does nothing for path B
           because Claude Code does not know your local dir is a git
           repo — you have to pull manually first.)

  Problem: /plugin install says "Plugin 'socratiskill' not found in
           any marketplace" right after a "Successfully added
           marketplace" message.
    Cause: The `marketplace add` actually failed. Claude Code prints
           a success line even when the path you gave does not
           contain .claude-plugin/marketplace.json (for example, if
           `~` was not expanded by the CLI, you typed a path that
           only partially exists, or the directory is empty).
    Fix:   cat ~/.claude/plugins/known_marketplaces.json
           If "socratiskill" is NOT listed, re-run with an absolute
           path and forward slashes (no tilde):
             /plugin marketplace add C:/Users/<you>/socratiskill
             /plugin install socratiskill@socratiskill
           Then verify again. `~/.claude/plugins/known_marketplaces.json`
           is the source of truth.


  ------------------------------------------------------------------
  CLAUDE REFUSES TO EDIT A FILE AND MENTIONS MY LEVEL
  ------------------------------------------------------------------
    Working as designed: above level 1, editing an existing file is
    yours to do. Check where you are with
    /socratiskill:socratic status.

    To get code again, pick one:
      /socratiskill:socratic ship "<why>"    temporary (10 min)
      /socratiskill:socratic level 1         Claude writes again

    If a Bash command was denied and it genuinely was not writing a
    file, it hit a false positive in the write detector — run it
    yourself in a terminal and mention it, do not let Claude invent
    a workaround.

  ------------------------------------------------------------------
  CLAUDE CREATED A FILE BUT LEFT EVERY FUNCTION EMPTY
  ------------------------------------------------------------------
    Also by design. At levels 3-5 a file it creates must contain zero
    executable statements: imports, types, signatures, comments and
    TODOs. The empty function you have to fill IS the exercise.

    If you want the bodies too, either drop to level 2 (trivial
    bodies allowed) or level 1 (it writes everything).

  ------------------------------------------------------------------
  I CANNOT TURN THE PLUGIN OFF AT A HIGH LEVEL
  ------------------------------------------------------------------
    You can: the gate always allows writes to ~/.claude/socratic/,
    so socratic off, level N and pause all work at any level. If
    something ever does block them, the filesystem escape is:

      bash <plugin-root>/scripts/pause.sh

    or set "global_level" to 1 in ~/.claude/socratic/profile.json

================================================================================
  7. DISABLE / PAUSE / UNINSTALL
================================================================================

  Four levels of "stop the plugin", from softest to heaviest:

  7.1 SOFT MUTE (state preserved, ~30 tokens/turn for silencer):
    /socratiskill:socratic off
    /socratiskill:socratic on        (to re-enable)

  7.2 TRUE BYPASS (state preserved, zero token cost):
    /socratiskill:socratic pause
    /socratiskill:socratic resume    (to come back)

    Equivalent shell scripts (useful from CI / scripts):
      bash ~/socratiskill/scripts/pause.sh
      bash ~/socratiskill/scripts/resume.sh

  7.3 PLUGIN-LEVEL DISABLE (Claude Code feature):
    /plugin disable socratiskill
    /plugin enable socratiskill      (to re-enable)

  7.4 FULL UNINSTALL — two equivalent paths:

    Inside Claude Code (preferred — no path juggling):
      /socratiskill:socratic reset force    (wipes state; hardened guards)
      /plugin uninstall socratiskill         (removes the plugin cache)
      /plugin marketplace remove socratiskill

    Or from the shell (same end result):
      bash ~/socratiskill/scripts/uninstall.sh
        (asks interactively whether to keep your journal/profile;
         use --keep-state or --purge to skip the prompt;
         --dry-run to preview)
    Then, inside Claude Code:
      /plugin uninstall socratiskill
      /plugin marketplace remove socratiskill

  Notes:
    - With the v0.2 plugin manifest install, the hooks are registered
      via hooks/hooks.json and NOT in ~/.claude/settings.json. The
      uninstall.sh hook-removal step only matters if you used the
      legacy install path.
    - uninstall.sh has hardened guards: it refuses to rm -rf any
      SOCRATIC_STATE_DIR that is not absolute, not under $HOME, lacks
      the .claude/socratic segment, or contains a `..` traversal.
